# Hackathon Tracker — frontend

SPA на React + TypeScript + Vite. Реализует пользовательскую и административную
части MVP согласно `docs/technical-specification.md` (разделы 11, 12, 14.2)
и контракту `docs/swagger.json`.

## Быстрый старт

Из корня репозитория:

```bash
make up            # вся инфраструктура: база, миграции, API, worker, фронтенд
make front MOCKS=1 # только фронтенд на моках MSW, backend не нужен
make down          # остановить
make help          # остальные команды
```

Порты переопределяются: `make up PORT=5188 API_PORT=8088`.

`make up` создаёт администратора `admin@example.com` с паролем `password123`
и переключает dev-сервер на реальный API через прокси `/api`.

Либо вручную из этой папки, на моках:

```bash
npm install
cp .env.example .env.local
npm run dev
```

Режим задаётся переменными: `VITE_ENABLE_MSW=1` включает моки MSW,
`VITE_API_PROXY=http://localhost:8080` направляет `/api` на реальный backend.
Переменные окружения перекрывают `.env.local`, поэтому `make` управляет
режимом, не переписывая ваш файл.

Учётные записи моков — пароль у обеих `password123`:

| Учётная запись      | Роль          |
|---------------------|---------------|
| `admin@example.com` | администратор |
| `user@example.com`  | участник      |

## Контракт — единственный источник истины

`docs/swagger.json` ведёт backend в формате Swagger 2.0. Фронтенд не
редактирует его, а конвертирует и генерирует из него типы:

```bash
npm run api:types    # перегенерировать типы после изменения контракта
npm run api:check    # упасть, если типы отстали от контракта (для CI)
```

Генератор (`scripts/generate-api-types.mjs`) делает три вещи помимо конвертации
в OpenAPI 3, и все три компенсируют особенности исходного контракта:

1. **`required`.** Контракт почти не размечает обязательность (10 схем из 79),
   из-за чего все поля стали бы `optional`. Обязательными считаются все поля,
   кроме перечисленных в `OPTIONAL` — этот список выведен из ТЗ.
2. **`format: date-time`.** В контракте нет ни одного такого формата, хотя по
   соглашениям API всё время передаётся в RFC 3339.
3. **Свёртка `enum` + `$ref`.** Генератор контракта дублирует enum рядом со
   ссылкой; без свёртки получается пересечение типов вместо объединения.

Все три правки исчезнут, как только те же сведения появятся в самом контракте.

## Проверки

```bash
npm run verify   # api:check + typecheck + lint + тесты
```

`src/shared/api/contract.test.ts` прогоняет каждый смоканный endpoint и
валидирует тело ответа против схемы контракта через ajv. Это ловит то, что
не видит `tsc`: расхождение фактических данных со спецификацией. Три теста в
конце файла проверяют сам харнесс — что он падает на пропущенном поле, неверном
типе и значении вне перечисления.

## Структура

```
src/
  app/          оболочка, маршруты, охранники, страницы-композиции
  modules/      доменные модули, зеркалят модули backend
  shared/       api-клиент, ui-примитивы, утилиты
  mocks/        MSW: данные и обработчики
  test/         настройка тестов и контрактный харнесс
```

Кросс-импорты между доменными модулями запрещены (раздел 14.2 ТЗ): обмен идёт
через `shared` и маршруты. Экран, которому нужно несколько модулей сразу,
живёт в `app/pages` — например `admin-hackathon-page.tsx`.

## Покрытие задач FE

Реализованы FE-01 … FE-23 из `docs/tasks.md`. Сверх бэклога закрыты группы
`Queries` и `Auth/all-sessions` раздела 17 ТЗ: экран дедлайнов
(`/admin/deadlines`), завершение всех сессий и подтверждение смены email
по ссылке из письма.

Контракт покрыт на 54 endpoint из 58. Оставшиеся четыре — `/healthz`,
`/readyz`, `/metrics` и `/ops/worker-heartbeat` — служебные пробы для
мониторинга и reverse proxy, экранов не требуют (задача INF-06).

## Что не реализовано

* **FE-24 частично.** Контраст токенов темы измерен и проходит WCAG 2.1 AA в
  обеих темах, разметка семантическая, фокус видимый, поля с метками. Но
  автоматической проверки axe и прогона в четырёх браузерах нет: нужен
  Playwright с установленными браузерами.
* **QA-05.** Сквозные тесты Playwright не написаны.
* **FE-10 частично — блокировано контрактом.** Деактивация своей учётной
  записи реализована. Удаления нет: раздел 2 ТЗ требует «запрос удаления своей
  учётной записи», но в `docs/swagger.json` такого endpoint нет — есть только
  `POST /me/deactivate` и административный `DELETE /admin/users/{id}`.
  Нужен endpoint на стороне backend.
