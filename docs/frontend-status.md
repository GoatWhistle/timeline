# Состояние фронтенда

Что из [tasks.md](tasks.md) закрыто на стороне SPA и что осталось. Перенесено
из удалённого `frontend/README.md` (часть VII.2 [плана рефакторинга](refactoring.md)):

## Покрытие задач FE

Реализованы FE-01 … FE-23. Сверх бэклога закрыты группы `Queries` и
`Auth/all-sessions` раздела 17 ТЗ: экран дедлайнов (`/admin/deadlines`),
завершение всех сессий и подтверждение смены email по ссылке из письма.

Контракт покрыт на 54 endpoint из 58. Оставшиеся четыре — `/healthz`,
`/readyz`, `/metrics` и `/ops/worker-heartbeat` — служебные пробы для
мониторинга и reverse proxy, экранов не требуют (задача INF-06).

## Что не реализовано

* **FE-24 частично.** Контраст токенов темы измерен и проходит WCAG 2.1 AA в
  обеих темах, разметка семантическая, фокус видимый, поля с метками. Но
  автоматической проверки axe и прогона в четырёх браузерах нет: нужен
  Playwright с установленными браузерами.
* **QA-05.** Сквозные тесты Playwright не написаны.
* **FE-10 частично — блокировано контрактом.** Деактивация своей учётной
  записи реализована. Удаления нет: раздел 2 ТЗ требует «запрос удаления своей
  учётной записи», но в [swagger.json](swagger.json) такого endpoint нет — есть
  только `POST /me/deactivate` и административный `DELETE /admin/users/{id}`.
  Нужен endpoint на стороне backend.

## Запуск фронтенда вне контейнеров

Обычный путь — `make dev` из корня: dev-сервер Vite работает в контейнере,
`src`, `public` и `index.html` смонтированы с машины, правки подхватываются по
HMR без пересборки образа. Запросы `/api` проксируются на контейнер API.

Если Node установлен на машине, фронтенд можно поднять и напрямую из
`frontend/`, на моках:

```bash
npm install
cp .env.example .env.local
npm run dev
```

Режим задаётся переменными: `VITE_ENABLE_MSW=1` включает моки MSW,
`VITE_API_PROXY=http://localhost:8080` направляет `/api` на реальный backend.
Переменные окружения перекрывают `.env.local`, поэтому запуск через Docker
управляет режимом, не переписывая ваш файл.
