# Telegram на сервере

Привязку аккаунта получает процесс `worker`. HTTP API запускается независимо от
доступности Telegram. Режимы получения команд взаимоисключающие.

## Long polling без входящего webhook

В серверном `.env`:

```dotenv
TELEGRAM_POLLING_ENABLED=true
TELEGRAM_WEBHOOK_URL=
TELEGRAM_TIMEOUT=10s
TELEGRAM_DIRECT_IPS=149.154.167.220
```

`TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_NAME` должны соответствовать одному боту.
IP выше отвечал на реальные запросы Bot API с VPS при диагностике; это результат
проверки, а не постоянный адрес, гарантированный Telegram. Список можно менять и
задавать через запятую. Пустое значение оставляет стандартное разрешение DNS.

При установлении соединения Telegram-клиент пробует указанные адреса по порядку,
затем обычный DNS. На попытку TCP-соединения отводится две секунды. URL, SNI и
проверка сертификата остаются для `api.telegram.org`; TLS не отключается.
Настройка применяется к отправке уведомлений и получению команд.

Worker удаляет установленный webhook без удаления накопленных сообщений и вызывает
`getUpdates` с ожиданием 25 секунд. Сетевой запас задаёт `TELEGRAM_TIMEOUT`.
После сбоя пауза увеличивается от одной до 30 секунд; остановка процесса прерывает
ожидание. У отправки уведомлений остаются существующие правила очереди и повторов.

Для одного токена должен работать ровно один polling-worker. Не включайте тот же
токен одновременно в локальной разработке и на сервере: получатели будут
конкурировать. Для разработки используйте отдельного бота.

Обрабатывается `/start <одноразовый токен>` в личном чате. Токен получается кнопкой
привязки Telegram в настройках Timeline. Ошибка базы не подтверждает обновление:
оно будет обработано повторно. Истёкший или уже использованный токен не блокирует
очередь. После перезапуска возможен повтор последнего сообщения; одноразовый токен
не позволяет повторно изменить привязку.

После изменения `.env` пересоздайте backend и worker штатной командой compose с
теми же файлами и тегом образа, которые используются в текущем развёртывании.
Обычный `docker restart` новые переменные окружения не подхватывает.

## Webhook

Для возврата к webhook выключите `TELEGRAM_POLLING_ENABLED`, задайте
`TELEGRAM_WEBHOOK_URL` и `TELEGRAM_WEBHOOK_SECRET`. Worker зарегистрирует адрес в
фоне и повторит регистрацию после временных ошибок. Нужен доступ Telegram к
HTTPS-адресу приложения. Этот режим не устраняет проблемы исходящего соединения.

## Проверка

Успешный ответ от корня `https://api.telegram.org` проверяет соединение, но не токен.
Команда `timeline telegram-check` выполняет `getMe` через тот же клиент, что и
worker, и не выводит токен. Запускайте её внутри backend-контейнера.
Проверяйте также `getWebhookInfo`, не публикуя URL с токеном в логах.
В режиме polling `getWebhookInfo.result.url` должен быть пустым; историческая
`last_error_message` сама по себе не описывает состояние polling.

В логах worker сообщение `Telegram polling started` означает успешное отключение
webhook. На уровне `debug` каждое успешное получение обновлений отмечается
`Telegram poll completed`. Окончательная проверка привязки: открыть свежую ссылку
из настроек, нажать Start в Telegram, затем обновить профиль Timeline.
