# Настройка рассылки Timeline через Gmail

Инструкция для отдельного Gmail или Google Workspace ящика.

## 1. Подготовить аккаунт Google

1. Войдите в нужный аккаунт Google.
2. Включите [двухэтапную аутентификацию](https://support.google.com/accounts/answer/185839).
3. Убедитесь, что аккаунт может отправлять письма через Gmail.

Для Google Workspace администратор организации может запретить пароли приложений. В этом случае потребуется разрешить их в политике организации или отдельно настраивать OAuth/SMTP Relay.

## 2. Создать пароль приложения

1. Откройте [раздел паролей приложений Google](https://support.google.com/accounts/answer/185833).
2. Создайте пароль для приложения `Mail` или назовите его `Timeline SMTP`.
3. Сохраните сгенерированный 16-значный пароль в менеджере секретов.

Обычный пароль аккаунта Google в Timeline использовать не нужно. Пароль приложения нельзя коммитить в Git или добавлять в этот документ.

Google отзывает пароли приложений после смены основного пароля аккаунта. В таком случае создайте новый пароль приложения и замените секрет окружения.

## 3. Настроить Timeline

В локальном `.env` или в секретах окружения укажите:

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=<полный адрес Gmail или Google Workspace>
SMTP_PASSWORD=<пароль приложения Google>
SMTP_STARTTLS=true
SMTP_TIMEOUT=15s

EMAIL_FROM=<тот же полный адрес>
EMAIL_FROM_NAME=Timeline
```

`SMTP_USERNAME` должен содержать полный email, включая домен. `EMAIL_FROM` лучше сделать точно таким же адресом: Gmail может отклонить отправителя, который не совпадает с авторизованным пользователем.

Для текущего SMTP-адаптера Timeline нужен порт `587`: приложение начинает обычное SMTP-соединение и затем включает STARTTLS. Порт `465` использует implicit TLS и текущим адаптером не поддерживается.

## 4. Вариант для Google Workspace SMTP Relay

Для корпоративной инфраструктуры Google рекомендует SMTP Relay. В этом случае администратор настраивает правило в Google Admin Console → **Apps → Google Workspace → Gmail → Routing → SMTP relay service**.

Сервер relay:

```env
SMTP_HOST=smtp-relay.gmail.com
SMTP_PORT=587
SMTP_STARTTLS=true
```

Способ аутентификации зависит от правила relay:

- при SMTP authentication нужны логин Google Workspace и пароль приложения;
- при IP-аутентификации логин и пароль не указываются, а сервер Timeline должен выходить со статического разрешённого IP.

Для первого подключения проще использовать `smtp.gmail.com` с паролем приложения. Relay имеет смысл для production-инфраструктуры с фиксированным IP и централизованными правилами отправки.

Официальная инструкция: [отправка писем из приложений через Google Workspace](https://support.google.com/a/answer/176600).

## 5. Проверка

Сначала отправьте одно письмо вручную из настроенного ящика на тестовый адрес. Затем проверяйте Timeline на одном получателе.

Проверяемые свойства:

- SMTP-подключение к `smtp.gmail.com:587`;
- STARTTLS;
- авторизацию паролем приложения;
- корректного отправителя и отображаемое имя;
- русскую тему и текст письма;
- доставку во «Входящие» или корректную маркировку спама;
- повторную попытку при временной ошибке.

Google указывает лимит до 2 000 сообщений в сутки для отправки через SMTP-сервер Gmail. Для массовых рассылок Gmail не является подходящим transactional-провайдером.

## 6. Безопасность

- Не передавайте пароль приложения в чат.
- Не добавляйте пароль в Git.
- Используйте отдельный пароль приложения только для Timeline.
- Включите 2FA для аккаунта Google.
- Для production храните SMTP-параметры в секретах окружения.
- Если пароль утёк или аккаунт скомпрометирован, отзовите пароль приложения и создайте новый.
